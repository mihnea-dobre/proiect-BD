# Isolation levels

Oracle accepta doua niveluri de izolare: **READ COMMITTED** si **SERIALIZABLE**.

Pentru a demonstra efectele nivelelor respective, vom folosi doua sesiuni SQL (`Sesiunea 1` - T1 si `Sesiunea 2` - T2) care manipuleaza date din sistemul de rezervare a locurilor de parcare, evidentiand fenomenele *dirty read*, *non-repeatable read* si *phantom read* si felul in care sunt tratate de Oracle prin **READ COMMITTED** (implicit) si **SERIALIZABLE**.

## 1. Dirty Read

**Definitie**: O tranzactie care citeste date modificate de o alta tranzactie, dar inca neconfirmate (uncommitted)

| Pas | Sesiunea 1 (T1) | Sesiunea 2 (T2) |
|-----|-----------------|-----------------|
| 1 | SET TRANSACTION ISOLATION LEVEL READ COMMITTED; | |
| 2 | UPDATE LOC_PARCARE SET disponibil = 0 WHERE id_loc = 5; (initial 1) | |
| 3 | Nu rulam COMMIT, trecem la T2 | SET TRANSACTION ISOLATION LEVEL READ COMMITTED; |
| 4 | | SELECT disponibil FROM LOC_PARCARE WHERE id_loc = 5; (1) |
| 5 | | COMMIT; |
| 6 | Abandonam modificarea, ROLLBACK; | |

- Rezultatul asteptat nu va fi 0, ci starea originala, adica 1. Fiindca T1 nu a facut commit, T2 a citit starea originala.

**In Oracle, Dirty Read este IMPOSIBIL. Nu exista READ UNCOMMITTED, si deci T2 mereu va citi pretul original cat timp nu am rulat COMMIT.**

## 2. Non-Repeatable Read

**Definitie**: O tranzactie care citeste aceeasi linie de doua ori si obtine valori diferite, deoarece o alta tranzactie a modificat si confirmat intre timp.

### Executie sub READ COMMITTED

| Pas | Sesiunea 1 (T1) | Sesiunea 2 (T2) |
|-----|-----------------|-----------------|
| 1 | SET TRANSACTION ISOLATION LEVEL READ COMMITTED; | |
| 2 | SELECT DISPONIBIL FROM LOC_PARCARE WHERE id_loc = 5; (1) | |
| 3 | | UPDATE LOC_PARCARE SET disponibil = 0 WHERE id_loc = 5; |
| 4 | | COMMIT; |
| 5 | SELECT disponibil FROM LOC_PARCARE WHERE id_loc = 5; (0) | |
| 6 | COMMIT; | |

- Rezultat: Mai intai 1, apoi 0. Acelasi select a returnat rezultate diferite.

**Acest fenomenen este posibil sub READ COMMITTED. T1 a rulat acelasi select, odata inainte ca T2 sa faca COMMIT la o modificare, si odata dupa. Rezultatele sunt astfel diferite.**

### Executie sub SERIALIZABLE

| Pas | Sesiunea 1 (T1) | Sesiunea 2 (T2) |
|-----|-----------------|-----------------|
| 1 | SET TRANSACTION ISOLATION LEVEL SERIALIZABLE; | |
| 2 | SELECT disponibil FROM LOC_PARCARE WHERE id_loc = 5; (1) | |
| 3 | | UPDATE LOC_PARCARE SET disponibil = 0 WHERE id_loc = 5; |
| 4 | | COMMIT; |
| 5 | SELECT disponibil FROM LOC_PARCARE WHERE id_loc = 5; (1) | |
| 6 | COMMIT; | |

- Rezultat: 1, apoi 1. Rezultatele raman consistente.

**Sub SERIALIZABLE, T1 citeste un snapshot al datelor de la inceputul tranzactiei, astfel incat orice modificare facuta de T2 nu afecteaza selectul lui T1. Non-Repeatable Read este IMPOSIBIL sub SERIALIZABLE.**

__Atentie__: Daca incercam sa modificam in T1 orice linie modificata in T2 sub SERIALIZED, vom primi eroarea `ORA-08177: can't serialize access for this transaction.`

## 3. Phantom Read

**Definitie**: O tranzactie executa aceeasi interogare de doua ori si obtine un set diferit de randuri, pentru ca o alta tranzactie a inserat/sters linii care satisfac conditia.

### Executie sub READ COMMITTED

| Pas | Sesiunea 1 (T1) | Sesiunea 2 (T2) |
|-----|-----------------|-----------------|
| 1 | SET TRANSACTION ISOLATION LEVEL READ COMMITTED; | |
| 2 | SELECT COUNT(*) FROM LOC_PARCARE WHERE id_zona = 1 AND disponibil = 1; (1) | |
| 3 | | INSERT INTO LOC_PARCARE VALUES (9, 'X-01', 1, 1); |
| 4 | | COMMIT; |
| 5 | SELECT COUNT(*) FROM LOC_PARCARE WHERE id_zona = 1 AND disponibil = 1; (2) | |
| 6 | COMMIT; | |

- Rezultat: 1, apoi 2. Rezultatele sunt diferite.

**Sub READ COMMITTED, schimbarea facuta de T2 este perceputa de catre T1 si afecteaza selectul. Inserarea unor date care implinesc conditiile impuse de T1 schimba valorea lui COUNT(*). Phantom Read este POSIBIL sub READ COMMITTED.**

### Executie sub SERIALIZABLE

| Pas | Sesiunea 1 (T1) | Sesiunea 2 (T2) |
|-----|-----------------|-----------------|
| 1 | SET TRANSACTION ISOLATION LEVEL SERIALIZABLE; | |
| 2 | SELECT COUNT(*) FROM LOC_PARCARE WHERE id_zona = 1 AND disponibil = 1; (1) | |
| 3 | | INSERT INTO LOC_PARCARE VALUES (9, 'X-01', 1, 1); |
| 4 | | COMMIT; |
| 5 | SELECT COUNT(*) FROM LOC_PARCARE WHERE id_zona = 1 AND disponibil = 1; (1) | |
| 6 | COMMIT; | |

- Rezultat: Va fi 1, apoi 1. Rezultatele raman consistente.

**Sub SERIALIZABLE, T1 vede acelasi numar la ambele COUNT-uri. Phantom Read este IMPOSIBIL sub SERIALIZABLE.**
